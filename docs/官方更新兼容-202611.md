# 官方更新兼容说明（2026-11 批次）

> 对应 QQ 机器人官方变更记录 **20261117 / 20261116 / 20261028**。本文记录 Gensokyo-ForSpark 的适配方式、使用示例与当前边界。
>
> 相关文档：[适配 API 清单](./适配API清单.md) · [DanielToyama 更新记录](./DanielToyama更新记录.md)

---

## 一、20261117

### 1. 群消息私聊回复

官方允许用**群消息事件的 `msg_id`** 调用单聊接口 `POST /v2/users/{user_openid}/messages`，私聊回复该群消息的发送者。

**适配方式**：直接使用 `send_private_msg`，同时传 `user_id`（群消息发送者）和 `message_id`（群消息事件里的 `message_id`）：

```json
{
  "action": "send_private_msg",
  "params": {
    "user_id": 800512121,
    "message_id": 1387423,
    "message": "你刚才在群里问的问题，私聊回复你"
  }
}
```

- `message_id` 为应用端看到的群消息 ID；非 `string_ob11` 模式下会自动经 idmap 反查为官方 `msg_id`
- 也可直接使用 `string_ob11: true` 模式，传官方群消息 `id`
- 前提：该用户与机器人是**好友关系**，否则官方拒绝
- 有效期与回复次数按**群消息规则**计算，且与群内回复**共用**次数上限

### 2. 群消息被动回复次数提升

官方规则（服务端校验，适配层无需配置）：

| 机器人身份 | 每条群消息被动回复上限 |
|---|---|
| 普通成员 | 5 次 |
| 机器人开发者是群主/管理员 | **50 次** |

群内回复与私聊回复共用同一 `msg_id` 的次数上限。

### 3. 群消息被动回复有效期

由 5 分钟延长至 **60 分钟**（群内回复与私聊回复均适用）。适配层不缓存有效期，直接透传 `msg_id`，由官方校验。

## 二、20261116

### 1. 获取用户基本信息

新增扩展 action：`get_user_info`。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `user_id` | string/int | 是 | 应用端用户 ID（`string_ob11` 时为 user_openid） |

- 官方接口：`GET /v2/users/{user_openid}/info`
- 响应 `data`：`user_id`、`nickname`、`avatar`、`union_openid`、`allow_proactive_msg`、`source`
- 频率：10 QPS；无好友关系返回 `40184001`，此时回退 username 缓存并标 `source: cache`
- `get_stranger_info` 也会优先调用该接口补充 `nickname` / `avatar` / `union_openid`，失败回退缓存

### 2. 单聊消息事件昵称、头像

`C2C_MESSAGE_CREATE` 事件中的 `author.username` / `author.avatar` 已映射到 OneBot 事件：

- `sender.nickname`
- `sender.avatar`（扩展字段）
- 顶层 `avatar`（兼容旧字段）

### 3. 群聊消息事件 `member_nickname`、头像

群消息事件新增的 `member_nickname`（群内昵称）映射：

- `sender.card` 优先取 `member_nickname`
- `sender.nickname` 取 `author.username`
- `sender.avatar` / 顶层 `avatar` 优先取官方 `author.avatar`，缺失时按 openid 生成

### 4. 群统一标识 `union_group_openid`

已加入以下 DTO / 事件输出（`union_group_openid` 字段，未绑定时为空）：

- 获取群基本信息响应 `data.union_group_openid`
- 群消息事件（`OnebotGroupMessage` / `OnebotGroupMessageS`）
- 机器人进群/退群、群成员增加/减少、入群申请、订阅消息状态变更等群事件
- 官方原始事件 DTO：`GroupInfo`、`GroupAddBotEvent`、`GroupMemberAddEvent`、`GroupMemberRemoveEvent`、`GroupJoinRequestEvent`、`SubscribeMessageStatusEvent`

> 该字段仅在机器人绑定第三方应用后由官方下发；未绑定为空，属正常现象。

## 三、20261028

### 图文卡片消息（`msg_type=8`）

新增两个扩展 action：

| Action | 场景 |
|---|---|
| `send_group_card_msg` | 群聊图文卡片 |
| `send_private_card_msg` | 单聊图文卡片 |

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `group_id` / `user_id` | string/int | 是 | 群 ID / 用户 ID（按 action 选择） |
| `title` | string | 是 | 卡片标题 |
| `description` | string | 是 | 卡片描述 |
| `url` | string | 是 | 点击跳转链接，**必须 https** |
| `pic_url` | string | 是 | 卡片图片，**必须 https** |
| `message_id` | string/int | 否 | 被动回复的群/单聊消息 ID |

示例：

```json
{
  "action": "send_group_card_msg",
  "params": {
    "group_id": 187781763,
    "title": "服务器维护公告",
    "description": "今晚 23:00 进行维护，预计 1 小时",
    "url": "https://example.com/notice",
    "pic_url": "https://example.com/banner.png"
  }
}
```

说明：

- 官方 `card` 结构为 `{"type":"tuwen","content":{"title","description","url","pic_url"}}`
- 图文卡片是独立消息类型，**不能与文本/markdown 混发**
- 群聊与单聊官方接口均支持 `msg_type=8`
- 入站消息 DTO 已增加 `card` 字段；OneBot 事件暂不把卡片转换为 CQ 段，应用端可直接读取原始事件中的 `card`

## 四、兼容状态与边界

| 能力 | 状态 | 说明 |
|---|---|---|
| 群消息私聊回复 | ✅ 已适配 | `send_private_msg` + 群消息 `message_id`；需好友关系 |
| 50 次被动回复 / 60 分钟有效期 | ✅ 官方服务端行为 | 适配层透传，无需配置；超限由官方报错 |
| 获取用户基本信息 | ✅ 已适配 | `get_user_info`；`get_stranger_info` 同步增强 |
| 单聊昵称/头像 | ✅ 已映射 | `sender.nickname` / `sender.avatar` / `avatar` |
| 群聊 `member_nickname` / 头像 | ✅ 已映射 | `sender.card` 优先 `member_nickname` |
| `union_group_openid` | ✅ 已透传 | 仅绑定第三方应用时非空 |
| 图文卡片发送 | ✅ 已适配 | `send_group_card_msg` / `send_private_card_msg`；`url`/`pic_url` 必须 https |
| 图文卡片入站转 CQ 段 | ⚠️ 未转换 | DTO 保留原始 `card`，OneBot 事件不生成 CQ 段 |

> 官方限制以服务端为准；频率、被动回复次数、60 分钟有效期等适配层不重复拦截，避免与官方规则不一致。

## 五、OneBot 调用兼容性

新增能力尽量沿用 OneBot v11 的标准 action / 参数 / 响应；没有标准对应项的才使用扩展 action。

| 能力 | OneBot 标准调用 | 本 fork 兼容方式 |
|---|---|---|
| 群成员列表 | `get_group_member_list`，参数 `group_id`，`data` 为成员数组 | ✅ 标准和 action/参数/响应；`cursor` 为扩展参数，内部自动翻页 |
| 群成员信息 | `get_group_member_info`，参数 `group_id`/`user_id`，`data` 为成员对象 | ✅ 标准 action/参数/响应 |
| 群成员移除 | `set_group_kick`，参数 `group_id`/`user_id`/`reject_add_request` | ✅ 标准单成员调用；`user_ids`/`member_openids` 为批量扩展 |
| 单人禁言 / 全员禁言 | `set_group_ban` / `set_group_whole_ban`，参数 `group_id`/`user_id`/`duration`、`group_id`/`enable` | ✅ 单人禁言为标准实现；⚠️ 全员禁言官方无写接口（`restrict_chat_setting` 仅支持 `members`，`global_rule` 只读），默认返回失败，需 `whole_ban_via_members: true` 开启实验性批量降级 |
| 群消息私聊回复 | `send_private_msg`，参数 `user_id` + `message_id` | ✅ 标准 action；`message_id` 使用群消息事件 ID |
| 用户信息 | `get_stranger_info`，参数 `user_id` | ✅ 标准 action；额外提供 `get_user_info` 扩展获取官方头像/union_openid |
| 群黑名单 | 无 OneBot 标准 | 扩展：`get_group_member_blacklist` / `add_group_member_blacklist` / `remove_group_member_blacklist` |
| 图文卡片 | 无 OneBot 标准消息段 | 扩展：`send_group_card_msg` / `send_private_card_msg`（`msg_type=8`） |

> `set_group_kick` 的 `reject_add_request` 在官方批量移除接口中近似映射为 `add_to_member_blacklist`；如需精确控制请使用扩展参数 `add_to_member_blacklist`。
